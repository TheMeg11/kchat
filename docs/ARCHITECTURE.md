# Architecture

Single service, single process, single PostgreSQL database.

- **Adapters** (`app/platform.py`): `TelegramAdapter` and `BaleAdapter` implement one shared async interface (send/edit/media/invoice/polling). Verified differences handled inside adapters: Bale has no `parse_mode` (Markdown is neutralized), no `sendSticker`, no webhook `secret_token`, prices in Rial, refund API absent. Telegram uses HTML parse mode, XTR Stars invoices, `refundStarPayment`.
- **Update ingestion**: webhook mode (secret path + `X-Telegram-Bot-Api-Secret-Token` for Telegram) with long-polling fallback when `PUBLIC_URL` is unset or setWebhook fails. Every update is deduplicated via the `processed_updates` unique index. 429 handling with `retry_after`, bounded retries (4), per-chat locks, graceful shutdown.
- **Matching engine** (`service.try_match`): FIFO queue table, `SELECT ... FOR UPDATE SKIP LOCKED` on Postgres, strict age-pool separation (13-17 / 18-60 — hard-coded, not configurable), permanent blocklist, recent-pair cooldown, gender-filter compatibility, coin charge only on successful match (affordability checked before any debit). Partial unique indexes on Postgres guarantee one active chat per user.
- **Economy**: append-only `coin_transactions` ledger with `balance_after`, idempotency keys for registration/daily/referral/payment/gender-filter, `with_for_update()` wallet row lock on Postgres, no negative balances, refund on failed delivery.
- **Moderation**: normalization (Arabic/Persian variants, ZWNJ/diacritics, repeats, leetspeak, homoglyphs, Persian digits) + token-aware dictionary + allowlist; contact filter (URL, t.me/ble.ir links, emails, @handles, Iranian mobile numbers, Instagram IDs). Progressive penalties 24h → 7d → 30d → permanent. 3 unique reports in 24h → automatic 24h ban (deduplicated per reporter/chat).
- **Privacy**: messages purge after 30 days (hourly job), media metadata only (no file contents), account deletion purges personal data, profile photos never relayed cross-platform (default avatar text instead). Backups keep full history inside encrypted archives (disclosed).
- **Backup engine** (`app/backup.py`): logical JSON dump of all tables → gzip → AES-256-GCM with scrypt KDF (`BACKUP_PASSWORD`) → SHA-256 → chunked ≤40MB parts → sent by the product Telegram bot to the owner. DB-locked against duplicates; daily at 03:00 Asia/Tehran; restore validates format/checksum/encryption/version, creates an emergency rollback snapshot, enables maintenance, restores, verifies consistency (orphan FK / wallet checks), auto-rolls-back on failure.
- **Super Admin web** (`app/webadmin.py` + `webadmin/index.html`): FastAPI implements the frontend's API contract exactly (`/api/admin/v1`): cookie sessions (HttpOnly/Secure/SameSite=Lax), in-memory CSRF tokens, Argon2id passwords, in-app TOTP (Google Authenticator compatible), recovery codes, login rate limiting, session revocation, security events, full permission model (owner/senior_admin/moderator/support with per-role customization by Owner).
- **Schedulers**: one asyncio loop inside the web process (purge, ban expiry, search/idle timeouts, match ticks, broadcast queue, daily backup) — no Redis, no separate worker.
